# Карта храмов — спецификация интеграции

Документ описывает подключение источника данных храмов к порталу ЯКатолик.

Связанные файлы:

- [`../js/config.js`](../js/config.js) — URL API
- [`../js/temples-api.js`](../js/temples-api.js) — клиентский адаптер
- [`../map.html`](../map.html) — UI
- [`../HANDOFF.md`](../HANDOFF.md) — общая интеграция

---

## 1. Архитектура на стороне портала

| Слой | Реализация |
|------|------------|
| UI | Leaflet, тёмные тайлы Carto (без API-ключа) |
| Данные | `GET {TEMPLES_API_BASE}/api/temples/search?bbox=…` |
| Fallback | Демо-набор точек при `TEMPLES_MODE=auto` / недоступности API |
| Маршрут | Внешняя ссылка на Яндекс.Карты |

UI и источник данных разделены: замена картографического движка (Leaflet → Яндекс.Карты JS API) не требует изменения контракта JSON.

---

## 2. Подключение API

### Конфигурация

```js
// js/config.js
TEMPLES_API_BASE: 'https://api.example.com'
TEMPLES_MODE: 'live' // или 'auto'
```

Альтернативы:

```
map.html?api=https://api.example.com&mode=live
```

```html
<script>
  window.VeraConfigOverride = {
    TEMPLES_API_BASE: 'https://api.example.com',
    TEMPLES_MODE: 'live'
  };
</script>
```

### CORS

```
Access-Control-Allow-Origin: https://<production-domain>
Access-Control-Allow-Methods: GET
```

### Приёмка

1. Открыть `map.html?api=…&mode=live`
2. Индикатор режима: **live**
3. Network: `…/api/temples/search?bbox=…` → `200` и непустой `features` в области с данными

## 3. Контракт API

### `GET /api/temples/search?bbox=lonMin,latMin,lonMax,latMax`

```json
{
  "features": [
    {
      "geometry": { "coordinates": [37.6289, 55.7609] },
      "properties": {
        "CompanyMetaData": {
          "id": "unique-id",
          "name": "Храм …",
          "address": "улица …",
          "City": "Москва",
          "Diocese": "Архиепархия …",
          "Kind": "parish",
          "Phones": [{ "formatted": "+7…" }],
          "Hours": { "text": "…" },
          "url": "https://…",
          "email": "…",
          "Photos": ["https://…"],
          "Tags": ["приход"],
          "description": "…"
        }
      }
    }
  ],
  "source": "db"
}
```

| Правило | Описание |
|---------|----------|
| Координаты | `[lon, lat]` (GeoJSON) |
| Пустой результат | `{ "features": [] }` |
| Stats (опционально) | `GET /api/temples/stats` → `{ "count": N, "source": "…" }` |

Клиент: `VeraTemples.search(bbox)` в [`temples-api.js`](../js/temples-api.js).

## 4. Предполагаемый стек бэкенда

Ориентир по ТЗ портала (diocese-API / отдача контента в клиент) и типовой схеме интеграции.

| Компонент | Вариант |
|-----------|---------|
| Язык / фреймворк | Python (FastAPI, Flask или Django REST) |
| Источник данных | Курируемая БД приходов ККЕР / существующий diocese-API приложения |
| Протокол | HTTPS JSON, bbox-поиск |
| Карты в приложении | Возможно Яндекс MapKit / JS API — на веб для v1 не обязателен |
| Тайлы на сайте | Carto / OSM (ключ не требуется) |

### Рекомендуемые схемы подключения

**A. HTTP-обёртка над существующей базой приходов**  
Имеющийся каталог (JSON/SQL/внутренний сервис) → тонкий endpoint §3 → портал. Источник истины остаётся на стороне бэкенда.

**B. Единый API с мобильным приложением**  
Тот же хост, что обслуживает приложение ЯКатолик. При отличии схемы полей — mapper/proxy к контракту §3.

**C. Экспорт точек из картографического SDK**  
Если точки уже ведутся в Яндекс.Картах / внутренней админке — достаточно отдавать id, name, lon, lat, address и метаданные в формате §3. Смена тайлового слоя на сайте — отдельный опциональный этап.

**D. Поэтапный запуск**  
До готовности API портал работает в `demo` / `auto`. После деплоя endpoint’ов — переключение `TEMPLES_API_BASE` и `mode=live`.

## 5. Вне зоны ответственности фронтенда

- Раздача тайлов карты  
- Внутренняя схема БД бэкенда (достаточно контракта §3)  
- Overpass / OSM как обязательный fallback  
- Ключ Яндекс.Карт для базового UI v1

## 7. Расхождение форматов

| Подход | Когда |
|--------|--------|
| Proxy/mapper на бэкенде | Предпочтительный: один стабильный контракт для веба |
| Правка `featureToTemple()` | Поля близки к §3 |
| Отдельный адаптер | Сильно отличающаяся модель; UI (`map-page.js`) не менять |

Принцип: UI портала зависит только от HTTP + JSON контракта §3.
